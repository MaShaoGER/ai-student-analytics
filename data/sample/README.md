# 模拟演示数据

这是一个仅用于开发和演示的虚构校园数据集，不对应真实学生。核心学习字段保持 OULAD 风格，额外提供出勤、作业、请假、学生档案与住宿数据。

- `learning_activity.csv`：学生-课程-开课期-周次粒度的学习活动事实表。
- `student_outcomes.csv`：学生-课程-开课期粒度的成绩与完成结果。
- `students.csv`：1,200 条学生档案，包括虚构显示名、性别、入学年份、学院、4 个专业、30 个行政班及学籍状态。
- `student_residences.csv`：4,800 条学生-学期住宿记录，包括校内/校外住宿、校区、宿舍楼、房间、床位、房间容量、单程通学分钟数；覆盖跨学期换宿舍和迁出校外。
- `leave_requests.csv`：请假申请明细，包括唯一申请号、粗粒度类型、申请/起止日期、周次、天数及已批准/未批准/已撤回状态。
- `attendance_weekly.csv`：230,400 条逐周出勤，每门课每周两课时（各 45 分钟），区分正常到课、迟到、早退、请假缺席与旷课，附迟到/早退分钟数和出勤率。
- `assignment_submissions.csv`：115,200 条作业明细，每次选课有 8 次作业，包含截止周与日期、提交日期、按时/迟交/未交状态、迟交天数、作业成绩。
- `student_term_summary.csv`：4,800 条学生-学期汇总，关联课程成绩、出勤、作业、请假申请数和批准天数。

现有成绩、活动量和课程完成率仍从前两个文件通过 DuckDB 查询。数据页已接入全部八张表的字段和缺失值统计。新增出勤率、作业完成率在 CSV 和学期汇总中已计算，但当前指标选择器和 AI 计划尚未扩展到这些指标，也不提供个人档案展示。

## 统计口径与关联

- 所有表通过 `id_student` 关联；住宿、请假和学期汇总还通过 `code_presentation` 对应学期；课程事实还需 `code_module`，不能只用学生编号关联后求和。
- `student_outcomes.csv` 原来的前五列和原有数值保留，末尾追加出勤课时、迟到/早退/请假/旷课次数、作业应交/已交/按时/迟交/未交数，以及三个比例和作业均分。
- 出勤率 =（正常到课 + 迟到 + 早退课时）÷ 应到课时 × 100。请假缺席不算实际出勤，仍包含在应到分母；五种到课状态互斥，合计始终等于应到课时。学期和课程汇总按总课时计算，不平均已四舍五入的比例。
- 三门选课每周分别安排周一、周三、周五上课，各两课时。仅“已批准”且日期覆盖该课的请假计入请假缺席；未批准或撤回不自动豁免旷课。请假天数按申请统计一次，不因涉及多门课而重复累加。
- 作业完成率 = 已交作业 ÷ 应交作业 × 100，迟交计入已交。按时提交率 = 按时提交 ÷ 应交 × 100。这两者均不同于 `completed` 对应的课程完成率。
- 未交作业的提交日期、作业分数为空；课程或学期无已交作业时，作业均分为空。这些是明确的“不适用”，不补为 0，也不算生成失败。`days_late=0` 需要结合提交状态解读。
- 成绩精度为百分之一分。新增均分先以整数百分之一分累加，再取平均并四舍五入到两位，避免二进制浮点累加导致 0.01 分差异；只在最终均分处舍入，不先平均课程作业均分。
- 校外住宿的宿舍楼/房间/校区为“不适用”，床位和容量为 0。校内宿舍每间最多四人，同一学期同一床位只分配一次；各学期保存独立住宿状态。
- 开学日期见 `summary.json` 的 `termStarts`。这是连续 16 周的简化校历，不单独模拟节假日和调课。最后一次作业允许在课程结束后 1–7 天迟交。
- 所有学生、宿舍、学习表现与请假均为合成内容；性别只用于宿舍分配一致性，不影响学习表现生成。

## 规模与覆盖

- 1,200 名匿名学生、10 门课程、4 个已结束学期（2024B、2024J、2025B、2025J）。
- 每名学生每学期选 3 门不同课程，共 14,400 条成绩与完成记录。
- 每次选课都有第 1–16 周记录，共 230,400 条周活动记录；没有活动的周明确记为 0。
- 课程包括程序设计基础、数据结构、数据库原理、Web前端开发、计算机网络、操作系统、高等数学、概率与统计、数据可视化、项目实践。`code_module` 使用这些唯一名称作为模拟课程标识。
- 包含持续活跃、逐渐进步、后期掉队、考前集中学习、低活跃高成绩、高活跃低成绩和全程不活跃等学习情况；课程难度与学期变化也会影响结果。
- 包含零分、满分、零活动、完成与未完成情况。`completed=1` 表示完成课程，不等同于成绩及格；完成率按该标记计算。

这些行为用于构造虚构数据。当前应用按课程或学期汇总，不提供学生行为分类或逐周趋势界面。

## 复现与回归

运行 `pnpm data:demo` 可用固定种子 `20261016` 重新生成八个 CSV 和 `summary.json`。新增校园数据使用独立随机序列，原有成绩、完成标记、学习活动与六组查询基准保持不变。汇总文件包含实际规模与独立 JavaScript 聚合的查询基准，应用展示仍查询原始 CSV。

可用 `pnpm data:demo --output-dir /tmp/campus-demo-check` 在独立目录验证复现，不覆盖工作区。

原来的 9 条结果、27 条活动记录保留在 `data/fixtures/golden/`，普通单元测试和隔离 HTTP 测试通过服务端 `DEMO_DATA_DIR` 使用它们。`lib/analysis/demo-data.test.ts` 验证扩充后的数据、档案与固定问题，`lib/analysis/campus-data.test.ts` 验证跨表一致性、比例口径、请假联动、作业空值和床位约束。
