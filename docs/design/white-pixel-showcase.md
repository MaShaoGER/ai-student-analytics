## 1. 目标与适用范围

将 AI 学生数据分析系统的前端展示，调整为具有作品集表现力的产品展示体验。让第一次打开页面的人能快速理解产品、看到分析成果，并通过简单操作体验核心能力。

本阶段优先设计页面表现、浏览节奏和演示交互，暂不以现有后端接口、登录流程或数据处理能力约束设计。演示使用明确标注的固定数据和预设情境，后续再讨论接入。

本文是新一轮展示前端的设计依据。此前液态玻璃工作台、深浅主题切换和三维数据城市等资料作为历史探索保留；其中与本文冲突的方向不继续作为新展示页面的要求。现有应用是否整体替换、如何保留工作台入口，留待实施阶段确定。本文不代表现有页面已经变更。

## 2. 已确定的方向

| 项目 | 当前约定 |
| --- | --- |
| 主背景 | 白色为主，可以用少量近白色区分区域 |
| 主题 | 只设计浅色体验，不考虑深色模式 |
| 装饰 | 可以使用像素风格，作为主要装饰语言探索 |
| 提示与强调色 | 不限定一个全站固定颜色，允许按内容和场景变化 |
| 布局 | 不做成由卡片拼成的 dashboard |
| 交互 | 直观、轻量，以滚动、点击、简单切换为主 |
| 展示强度 | 有视觉表现力，但不采用需要大量操控的沉浸式展示 |
| 工作重点 | 前端表现与演示体验优先，暂不处理后端对应关系 |

以下关于章节、色彩规则、尺寸和动效的内容属于建议方案，可在视觉稿中调整。

## 3. 整体气质

关键词：明亮、开阔、清晰、有趣、精致。

用大标题、留白、图表和少量像素图形形成识别度。页面应有完整的视觉重点与浏览节奏，让人愿意继续向下看，同时能随时找到体验入口。

像素语言用于体现数据的颗粒、聚合、排列和变化。正文、表格、表单及图表标签保持现代、清晰的阅读体验。避免把整个产品做成复古游戏界面。

## 4. 页面结构与布局

采用纵向展开的产品展示页。通过留白、细分隔线、文字尺度与内容构图区分章节。主内容直接布局在白色页面上，避免每一段都包进圆角容器。

### 建议的首页顺序

| 章节 | 展示内容 | 主要交互 |
| --- | --- | --- |
| 导航 | 产品名称、能力介绍、演示入口、案例入口 | 锚点跳转；保留一个明显的“体验演示”按钮 |
| 首屏 | 一句产品价值主张，一幅数据与像素组合的主视觉 | 点击体验；主视觉可以轻微自动变化 |
| 能力展示 | 从提问到图表，再到结论的简短过程 | 切换“问数据 / 看趋势 / 读报告”等能力标签 |
| 交互演示 | 一组精选问题，以及对应的图表、解释和筛选条件 | 选择问题、切换课程或时间范围、查看详情 |
| 分析案例 | 两到三个有明确问题和结论的案例 | 在页面内展开案例，或进入独立案例页 |
| 成果与收尾 | 报告预览、主要能力总结、再次体验入口 | 查看报告、返回演示 |

建议首屏文案示例：“让学习数据，变成看得懂的答案。”文案仅用于定调，产品名称和正式标语尚未确定。

### 布局规则

新增网格方向：主视觉可以采用一整幅连续画面，叠加局部可见的细线网格。文字、光影和像素共享布局基准，大标题可跨格，小标签沿格线对齐。网格单元无需分别成为容器或交互入口。

| 参考 | 提取的方法 | 项目中的建议应用 |
| --- | --- | --- |
| 用户参考 A：蓝色人像网格 | 连续画面、细线分区、交点星芒、贴边短文 | 首屏使用浅灰细线与少数交点微光，保留大面积白底 |
| 用户参考 B：天空与大字切片 | 跨格排版、局部雾面、疏密变化 | 允许标题跨多个单元，少量装饰区域采用半透明色泽；正文保持清晰 |
| 用户参考 C：图像与像素过渡 | 方块细分、边界溶解、图文衔接 | 将柔光或抽象主视觉沿网格细分，逐步过渡到白色内容区 |

主视觉网格建议桌面 4–6 列，移动端减少到 2–3 列，装饰像素使用主网格的细分单位。线宽可从 0.5–1px 试起；小标签距离格线约 16–24px。微光只出现在少数交点，避免全屏星芒。优先应用于首屏、案例封面和章节衔接，正文、表格与数据图表区域减弱装饰网格。装饰线不作为图表坐标或数据编码。

- 每个章节只设置一个主要视觉焦点，避免多个同等重量的图表争抢注意力。
- 数据结果可以采用通栏图表、左右分栏、开放式列表和大幅案例展示。
- 指标使用连续排版或带细分隔线的数据行，不做四张或六张独立 KPI 卡片。
- 首屏与案例适当使用非对称构图，章节之间调整图文比例，避免整页重复同一种布局。
- 演示输入框、下拉菜单、提示浮层和报告纸张可以有边界；“不做卡片 dashboard”不限制必要的控件容器。
- 常规页面不使用持久侧栏、密集筛选工具条或多面板工作台作为整体骨架。
- 桌面正文建议最大宽度约 1200–1320px；主视觉可以更宽。具体尺寸随设计稿校准。

## 5. 像素装饰语言

### 建议使用位置

- 标题旁的小型符号、章节编号、箭头和角标。
- 首屏中的像素点阵、数据方块或简单图形。
- 演示状态中的聚合、排列、填充动画。
- 案例切换时的小范围像素过渡。
- 页尾或留白区域中的少量趣味元素。

### 统一规则

- 用同一套基础网格生成装饰，建议以 4px 或 8px 为起点；在同一构图内保持颗粒尺度有规律。
- 像素边缘保持清晰，避免用模糊发光和厚重阴影包裹像素图案。
- 同一屏以一个主要像素图形为主，其余装饰降低存在感。
- 不在长正文和中文说明中使用像素字体；图标不能牺牲语义辨识度。
- 图表的数据点与装饰点阵应能区分。图例、坐标和数值不能被装饰遮挡。
- 装饰不承载必须发现的操作入口；可点击元素通过文字、形态和焦点状态明确表达。

可以尝试“散点 → 有序排列 → 图表”的视觉母题，让装饰与数据分析过程产生联系。不要求整站都采用点阵动画。

## 6. 白色基底与多色提示

建议基础色采用白色、近白色、深灰文字和浅灰分隔线。大面积背景维持明亮，避免连续的大面积深色章节。

“提示色不固定”的建议解释：不同章节或任务可以拥有不同强调色，同一种交互状态仍保持一致。颜色服务于内容识别，不在每次刷新或点击时随机改变。

| 用途 | 建议规则 |
| --- | --- |
| 基础背景 | 白色为主，近白灰用于必要的局部区域 |
| 正文 | 深灰为主，次要文字使用仍清晰可读的中灰 |
| 章节强调 | 可从蓝、橙、紫、绿等色系中选择，每个章节确定一个主强调色 |
| 当前选中 | 跟随所在章节的强调色，同时有下划线、形态或文字标记 |
| 成功、警告、错误 | 各自使用稳定的语义颜色，并附文字或图标 |
| 图表系列 | 同一课程、群体或指标跨视图保持稳定映射，不随章节配色任意改色 |
| 主操作 | 通过尺寸、位置和实色填充保持突出，不只依赖某个固定色相 |

避免一屏同时使用多个高饱和强调色。浅色装饰不直接用于小字号正文。普通正文对比度建议至少 4.5:1，较大文字和必要控件边界按相应可访问性要求检查。最终色值在视觉稿中确认，当前不冻结品牌色。

## 7. 字体、边界与材质

- 中文正文采用清晰的现代无衬线字体，标题依靠字号、字重和换行建立层级。
- 像素字形只用于少量短标签或装饰，不强制引入额外字体。
- 数字和坐标保持易读，变化中的数值可使用等宽数字以减少跳动。
- 小圆角可用于按钮和输入框；避免所有内容统一套大圆角、阴影和描边。
- 玻璃折射、全屏模糊和光学背景不作为本方向的主要材质。
- 以白底、细线、轻微底色变化为主，浮层才使用必要的轻阴影。

## 8. 交互与动效边界

### 新增光影方向：白底上的局部流光质感

在白色基底和像素装饰上增加轻微光影层次。当前档案仅呈现静态材质，不代表动画已实现。

| 表现 | 使用位置 | 约束 |
| --- | --- | --- |
| 局部柔光 | 首屏留白、主视觉背后 | 淡紫、浅桃、嫩绿渐隐到白色；避开长正文和数据密集区 |
| 像素微虹彩 | 少量主视觉装饰块 | 块内有轻微高光和色泽变化，外轮廓保持清晰；不用于所有图表数据点 |
| 细线流光 | 章节分隔、选中提示、演示完成反馈 | 细线中局部亮起；文字和数值保持稳定实色 |

建议每屏只设置一个主要光区。色板中的强调色仍负责内容识别，光影是额外的材质层。避免满屏彩色渐变、厚重光晕、玻璃卡片墙和高频闪烁。若后续增加移动光源，先尝试缓慢、低幅度的变化；减少动态效果模式下使用静态版本。验证时以正文可读性和页面响应速度为先。

用户通过正常滚动即可完整了解产品。点击和简单切换用于进一步体验，不要求先学会操控场景。

### 可以采用

- 章节进入时的轻微淡入或短距离位移。
- 标签切换后，图表、标题和解释同步更新。
- 像素图形的小范围排列、跳动或逐步填充。
- 按钮悬停、按下和键盘焦点反馈。
- 简短、可跳过或可重播的自动演示。
- 图表点击、聚焦或轻触查看详情；桌面悬停作为补充。

### 不作为主要体验

- 第一人称漫游、驾驶、游戏式寻路和复杂镜头控制。
- 旋转三维场景才能找到信息，或多步骤拖动才能完成基本浏览。
- 劫持滚动、强制横向探索、长时间锁屏过场。
- 大量跟随鼠标的元素、自定义光标干扰点击、持续大幅视差。
- 仅靠悬停才能看到的关键内容，以及自动播放的声音。

建议微交互约 120–200ms，内容切换约 200–350ms，装饰序列控制在约 1 秒以内。动画优先说明状态变化；减少动态效果模式下直接呈现最终状态。首屏文字和主按钮不等待动画结束才可用。

## 9. 前端演示规则

第一版建议集中完成一条完整路径：选择问题 → 展示分析过程 → 出现图表与解释 → 切换条件 → 查看报告。

- 使用固定演示数据，数据、图表和结论相互一致，并清楚标注“演示数据”。
- 提供少量精选问题，保证每条都能走完体验；不为展示数量加入无响应按钮。
- 如保留自由输入，明确可演示的范围。未覆盖的问题给出可选示例，不伪装成已完成真实分析。
- 过程动画短而明确，不制造长时间假等待；提供“重新演示”。
- 当前条件、当前选择和结果变化都要可见，切换后不能只改变装饰颜色。
- 报告预览对应当前演示结果。下载、分享等能力只有实现后才显示为可操作入口。
- “无需后端即可演示”是本阶段的实现条件，不在页面中堆放接口、模型配置等开发说明。

## 10. 移动端与使用体验

- 移动端采用单列，保持问题、结果和解释的阅读顺序。
- 像素装饰缩减或重排，不压缩文字和操作空间。
- 多个能力标签可以换行或使用明确的选择控件，不依赖隐藏的横向手势。
- 图表保留必要标签；复杂图表提供摘要或简化视图。
- 关键操作支持键盘与触控，装饰元素不进入键盘焦点顺序。
- 动效和视觉资源按需加载，页面不因装饰资源尚未就绪而空白。

## 12. 后续设计与验收

建议先完成首屏、能力展示和一条可操作演示，再扩展案例与报告章节。先验证白底、像素图形与开放式布局能否形成完整气质，再补充装饰动画。

设计稿和前端预览按以下标准检查：

- [ ] 白色是主要底色，没有深色模式入口和配套设计要求。
- [ ] 首屏能够快速说明产品用途，并提供明显的体验入口。
- [ ] 主要内容以开放排版组织，没有 KPI 卡片墙或 dashboard 骨架。
- [ ] 像素装饰使用统一规则，文字和图表仍然清晰。
- [ ] 章节允许不同强调色，状态语义和图表类别颜色保持稳定。
- [ ] 普通滚动即可浏览完整内容，关键演示只需直观点击或切换。
- [ ] 演示问题、筛选、图表、解释和报告相互对应。
- [ ] 手机、键盘操作和减少动态效果模式下可以完成主要体验。
- [ ] 动效没有阻挡首屏内容，也没有让用户被迫等待。

待视觉稿验证的选择包括：像素图形是否加入角色、首屏使用哪一种数据构图、具体色板与字体，以及展示页和原工作台的入口关系。它们不改变本文已确定的设计边界。
