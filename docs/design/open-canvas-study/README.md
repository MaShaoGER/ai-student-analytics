# 开放画布 · Opus 概念循环稿

2026-11-02。**Opus 本轮已完成前端与交互改版；主代理核对数据并补齐打断、画法历史与浏览器验收。** 这是设计讨论稿，不是正式应用切换。

后续用户已授权并完成正式项目集成，见[总方案第17节](../open-canvas-exploration.md#17-正式项目集成当前实现)和[工作台指南](../../workspace-guide.md#连续探索)。本目录继续作为独立设计对照，不是正式查询的数据源。

本轮按用户“数据结构 → 出勤率 → 关联图 → 另一门课 → 继续”的例子纠正操作逻辑，不再沿用上一版“进入成绩分布”的单按钮导航。总方案见[开放画布设计深化](../open-canvas-exploration.md#11-代表性浏览路线课程指标关系循环)。

## 打开

直接打开 [index.html](index.html)，或在本目录运行：

```bash
python3 -m http.server 4186 --bind 127.0.0.1
```

访问 <http://127.0.0.1:4186/>。无需安装依赖、登录、数据库或模型；它不是正式应用端口。

## 按这个顺序试

1. 首页点 **数据结构**。左边是该课统一指标表，右边只显示数据结构的六项指标，不再继续画全体课程。
2. 点右侧 **点位 / 雷达 / 柱形**。只是表达改变，仍是同一门课、同一组指标；均分单位是“分”，其它是“%”，都有标注。
3. 点左表里的 **出勤率**，或图里的出勤指标。当前中心变为出勤率，左边列出出勤率—成绩、出勤率—通过率、出勤率—教学周、出勤率—学科。
4. 选 **出勤率—通过率**，再换点位。保持数据结构范围以及同一组出勤区间和人数，不暗中筛人。
5. 点关系里提供的 **均分 / 通过率** 等指标，它又成为新的中心。其它指标也能继续点，不是只有出勤这一条有效。
6. 回到出勤率，明确选 **出勤率—学科**，才扩大到 18 门课。两种画法都只表达“课程 × 出勤率”，不会换成另一种双变量分析。
7. 点其中的 **数据库原理**，回到这门课的统一指标表；继续点作业、均分或其它指标，循环重新成立。
8. 左下进 **探索全览**。前后是主题过程，左右是已看过的画法；点具体卡片恢复主题与画法。
9. 右下切到 **AI 布局**，可移除上下文、保留问题草稿，再返回原场景与阅读位置。不会发送内容，也不会生成假回答。

## 左右内容的规则

| 当前中心 | 左侧 | 右侧 |
| --- | --- | --- |
| 课程 | 该课六项指标整理表，指标行可点；目标达成率缺定义单独说明 | 同一课程指标数据的柱形 / 点位 / 雷达 |
| 指标 | 围绕指标的关系主题，以及当前课程其它指标 | 当前关系数据可用的两种表达 |
| 跨课程比较 | 当前指标关系与原始课程上下文 | 18 课同一指标的排序条 / 点位；点课程重建课程中心 |

切换图表形式不增加探索主题；打开另一指标或关联主题才增加步骤。快速连点取消未提交的旧目的地，不把中间页也记成一次浏览。

首页固定可达，最近 5 个主题在全览展开，较早主题可取回。回旧主题新开一条路线时，离开的后续段收进“更早探索”，不删除。状态仅保留在当前页面内存；刷新回到起点，不声称已实现持久化。

## 当前视觉与动作

Opus 保留开放画布与四角，把原先空旷的单按钮层改为有真实读数的统一表和可继续点的关系列表。桌面左右组织内容，窄屏按阅读顺序排布；不是新建后台导航或平台。

当前颜色仍为纸面 `#fbfcff`、正文 `#17243a`、辅助 `#64748b`、数据/交互 `#4064ec`，课程锚点用 `#b7813d`。系统无衬线中文；设计稿不覆盖正式视觉规范。

- 页面切换：180ms 舞台失焦到 10px、透明度 .35；切换内容后 420ms 从 12px 聚焦到清晰。
- 入场带 24px 局部蓝色柔光，曲线 `cubic-bezier(.22,.68,.18,1)`；四角不模糊。结束后去掉临时过滤效果。
- 同主题换画法原位更新，主题、范围与分母不变，全览横向记录访问过的画法。
- 系统减少动态或右上说明菜单的“减少动态”勾选后，直接清晰更新。

## 数据与口径

全部来自仓库 `data/sample/` 的**合成校园演示数据**，不对应真实学生，不构成现实教学发现，不包含学生 ID 或个人记录。

- `data.js`：课程成绩分布、均分、人数、完成标记、周活动等原有聚合。
- `relations-data.js`：2025J 全部 18 课的六项指标、周出勤、出勤五箱与成绩/通过率关系、作业计数和指标定义。
- 出勤率按总课时加权；出勤分箱 `[0,20)…[80,100]`，末箱含 100。成绩与通过率使用同一分组人数；1–2 人的出勤组人数与率均隐藏，空组与隐藏不同，不补零。
- 通过率按成绩 `>=60` 计算；课程完成率按 `completed` 计算。教学目标达成率缺少目标定义，明确显示未计算，不能拿课程完成率代替。
- 数据结构 · 2025J：200 人，均分 **66.91 分**、出勤率 **83.45%**、通过率 **75.50%**、课程完成率 **90.50%**、作业提交率 **87.69%**、按时提交率 **71.81%**。作业应交 1600、按时 1149、迟交 254、缺交 197。
- 出勤分箱关系是描述性聚合，不表示出勤对成绩或通过率的因果作用。全科比较中每个点代表课程，不代表个人。

此独立样稿不接正式API、权限、账号、报告、预算或产品AI，其公开合成数值不作为生产数据保护验收。正式应用随后已按用户授权接入同一探索逻辑与真实查询，`.interface-design/system.md`已同步；不要把本节样稿阶段的“未改正式应用”当作当前状态。

## Opus 与实际验证

初次改版调用在写出部分脚本后遭上游 404 中断。用户要求重试后，`pop-claudekiro/claude-opus-5-5:low` 实际完成三份前端文件。主代理不是把其它模型的稿冒称 Opus；同时也没有把 Opus 交付直接当作验收通过。

主代理实际使用 Edge：

- 桌面 1440×1000、窄屏 390×844 走通课程 → 指标 → 关系 → 跨科 → 新课程 → 再点指标；320px 课程与关系画面无页面横向溢出。
- 课程三画法同指标；出勤分组柱 / 点同数值、同样本；跨科排序 / 点位同 18 课读数。
- 均分、通过、课程完成、作业与按时指标逐项打开并切换提供的画法；出勤小组隐藏保持。
- Tab 进入雷达图 SVG 指标并 Enter 继续；快速连点不产生中间页；全览保留同主题不同画法、折叠页可恢复、旧后续段未删除。
- AI 上下文准确带上当前课程、关系与画法；移除不丢草稿，往返草稿保留，窄屏阅读位置实测 408px → 408px。
- 系统与菜单减少动态；实际观察 420ms 聚焦及四角清晰，另留暂停采样的模糊中间帧。
