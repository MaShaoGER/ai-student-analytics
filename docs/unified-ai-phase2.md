# AI 统一对话第二阶段：接好统计与展示（实施记录）

实施日期：2026-10-19。分支：`codex/competition-phase2`（用户选择“方案 B”，在既有第二阶段分支上继续）。本轮只实施[统一对话路线图](unified-ai-workflow-roadmap.md)的**第 2 步「接好统计与展示」**，未实施第 1、3、4 步。

## 本轮做了什么

### 1. 统一统计结果契约（地基）

新增 [`lib/ai/result-contract.ts`](../lib/ai/result-contract.ts)：

- `ResultRef`：`resultId`、数据集与版本、指标、课程、学期、筛选、粒度、单位、最小样本、样本量、范围说明、限制。
- `FactRef`：`factId` + `resultId` + 结构化数值（值/单位/样本量/分子/分母）+ 限制。
- `resultId` 由范围内容确定性派生（16 位十六进制指纹），因此**同一范围的表格与图表天然共享同一 id**；`factId` 绑定到所属 `resultId`。
- `danglingFactRefs()` 用于检查“引用了不存在的统计结果”的事实，这类事实不能当作已验证结论输出。
- 版本常量 `DATASET_VERSIONS` / `METRIC_VERSION` 与 `data/schema/*.json` 对齐，并由测试锁定；注释明确写这是**冻结定义文件的静态版本**，不是按文件内容动态计算的版本（路线图 P2 仍未实施）。

新增 [`lib/ai/artifact-results.ts`](../lib/ai/artifact-results.ts)：把既有 5 种 `ChatArtifact` 派生为 `{ resultRefs, factRefs }`。派生过程**不查库**，只使用 artifact 里已有的数据，所以展示方式变化不会产生新的结果身份或新的查询。

接入位置：`ChatResponse` 增加 `resultRefs?` / `factRefs?`（扩展而非替换，旧字段保持兼容）；`lib/ai/comprehensive.ts` 与 `lib/ai/conversation.ts` 两条响应路径都输出该契约。

### 2. 成绩分布改为按范围下推查询

`scoreDistribution(datasetId, options, scope)` 新增可选 `scope`，把课程/学期谓词**放进 SQL 内部**（`distributionPredicate`），使直方图、合格人数与返回分组都描述同一范围。

改动前：综合分析里的分布工具先拉全量数据，再在内存里过滤单门课程。改动后：查询本身就只读取目标范围。

**注意一处真实返工**：首轮实现只给 `scoreDistribution` 加了 `scope` 能力，但综合分析主链路（`comprehensive.ts` 的 `score_distribution` 分支）没有把第三参传进去，实际上仍是“全量拉取 + 内存过滤”。独立核验发现后已修正，并补了断言第三参的回归测试。这条教训是：只测函数能力、不测调用接线，会得到“测试全绿但主链路没改”的假通过。

空值与空白标签被忽略（曾出现 `= '  '` 静默匹配不到人的缺陷，已修复）。

### 3. 缺勤统计契约与工具（路线图 §4.1 / §4.3）

新增 [`lib/analysis/absence-stats.ts`](../lib/analysis/absence-stats.ts) 与 `absenceStats()`：

- **三种单位严格区分**：`sessions`（课时，每课时 45 分钟）、`students`（去重人数）、`days`（请假天数）。
- **人次与人数分开报**：`totals.studentCourseCount` 是各课程受影响人数之和（**人次**），`totals.distinctStudents` 是跨课程去重后的人数。真实数据 2025J 下两者分别为 3,184 与 1,194，相差 2.7 倍；直接相加当人数会显著夸大受影响范围，因此拆成两个字段并在事实文本与模型提示词中明确禁止混用。
- **两种口径严格区分**：`absence = 已批准请假缺席 + 旷课`；`unexcused` 只算无批准请假的旷课；`excused` 只算请假缺席。
- **不允许换算**：请假天数不等于缺勤课时，请求 `days` 时返回 `supported: false` 并说明原因，而不是换算。
- **OULAD 明确不支持**：返回 `supported: false` 与固定说明，不用活动量替代。
- **缺字段时返回不支持而不是驱动报错**：先 `DESCRIBE` 探测真实列，缺列时如实说明（此缺陷是测试真实发现的）。
- **最小样本按组内有有效记录的学生数**计算，不是按“有缺勤的人数”计算——后者会泄漏受影响人数。

新增工具 `absence_stats` 接入综合分析工具循环，带目录校验（课程/学期必须在真实目录中）与预算/取消语义。模型提示词同步改为“缺勤数字只能来自 `absence_stats`，单位不可互相换算”。

**返工项（核验发现）**：缺勤结果最初不产生任何 `ChatArtifact`，导致纯缺勤回答的 `resultRefs` 为空、`kind` 落到 `clarification`，用户会看到与实际回答无关的“请明确要分析的指标”。已补 `describeAbsence()` 为缺勤结果建立 `ResultRef`/`FactRef`（`kind: "absence"`），并修正 `kind` 判定使用合并后的结果而不是仅看 artifact。同时修复 UI 折叠块的显示条件：原先要求 `!response.steps?.length`，而综合分析每轮都有 steps，导致“数字从哪来”在最重要的路径上**永不渲染**。

### 4. 界面：`数字从哪来` 默认折叠

`components/ai-conversation.tsx` 把事实列表改为 `<details>`，默认折叠、展开入口始终可用；有 `resultRefs` 时显示统计结果数量；命中 `factRefs` 的事实附带 `factId`。样式补在 `ai-conversation.module.css`，含键盘焦点可见样式。

## 已知限制

1. `resultId` 指纹是非加密哈希，只用于身份识别，不承担任何权限或防篡改语义；它对不同用户是确定性的，未来若做缓存**不可**按 `resultId` 跨用户复用。
2. 数据集版本是静态声明版本，数据文件被替换时不会自动改变；路线图的动态版本管理仍未实施。
3. 关系分析与全景结果只提供共现/密度聚合，不提供相关系数；`binnedCorrelation` 只是对可见分档的估算，未纳入 `FactRef`。
4. 缺勤的请假天数按学期统计，请假表没有课程列，因此**不做按课程的分配**；总量单独给出，文案明确“按学期统计、不含课程维度”，不声称“同一范围”。
5. `unit=days` 会进入工具调用并返回 `supported:false`（不换算、不返回数字，也不产出 `ResultRef`），但 UI 没有预先禁用该选项。
6. 已删除没有数据支撑的 `periodsPerSession` 字段：`student_outcomes.scheduled_sessions` 已是课时合计（全部为 32），再暴露“每次 2 课时”会被误乘。行级 `approvedLeaveDays`（恒为 0）同样已删除，避免客户端误用。
7. 请假表缺失时降级为 0 天而不是 IO 错误，缺勤课时仍正常返回。
8. 缺勤统计每次请求会多一次 `DESCRIBE` 以探测字段；未做列信息缓存，属于以正确性换取的额外开销。
9. 事实与 `factId` 的对应关系由服务端单一来源生成（`describeAbsence` 同时产出文本与 id），但 analysis/studio 路径仍只有部分事实带 id；UI 对无 id 的事实不显示编号。
