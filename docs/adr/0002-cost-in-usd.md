# ADR 0002：成本统一按美元（USD）记账，人民币单价人工换算

- 状态：已采纳（2026-10-18）
- 背景材料：`output/ai-review/OVERALL-ai-review.md`（C 段）、`output/ai-review/people-and-process.md`（C3/C4，均为本地审计材料）、[百炼接入](../bailian-qwen.md)、[工作台使用指南](../workspace-guide.md)

## 决策

应用内所有费用字段、预算与用量统计**统一使用美元（USD）**，单位为“USD / 百万 token”。服务商若只给人民币价格，由管理员按公式 `人民币单价 ÷ 每美元对应人民币金额` 换算后填入；汇率本身不落盘，但必须在 [AI 交接单](../ai-handover.md) 中手写记录“日期 + 汇率”。

## 背景

- 代码与界面早期已按 USD 实现（`lib/security/ai-cost.ts`、管理页费用卡），预算默认值 0.1 / 5 / 20 / 200 也是 USD 口径。
- 真实服务商中，百炼按人民币计价、智谱免费模型为 0；管理员需要把人民币换算成 USD 才能填表。
- 审计发现：人民币换算依赖人工心算，汇率不落盘，换人无法复核；应用估算与实际账单存在差异（折扣、免费额度、缓存），且 `CostRecord` 没有用户维度，回答不了“哪位老师用了多少”。

## 备选方案

1. **全站改人民币（CNY）**：对国内老师直观，但要改数据库字段、界面、预算与历史记录，且 OpenAI 官方等按 USD 计费时会产生反向换算。成本高，收益有限。否决。
2. **双币种并存（录入双价、显示双价）**：界面上“看起来对”，但汇率仍需人工维护，账实差异不会因此消失。否决。
3. **实时汇率 API + 自动换算**：引入外部依赖与网络失败面，演示环境不可控；且真实账单以服务商为准，自动换算只增加“精确的错觉”。暂缓。
4. **USD 单一记账 + 汇率记录在交接单（本决策）**：保持既有实现与默认预算不变，把不可复核的部分显式记在交接单里。

## 后果

- **正面**：不改代码与数据格式；预算/费用/限流口径一致；切换服务商只需重填单价；汇率争议有书面依据。
- **代价**：填单价前必须人工换算，容易出错；估算不等于账单（`estimated: true`），不能作为财务凭据；汇率变化后需人工更新单价并重记。
- **已知边界**：`CostRecord` 无 `userId`、管理页只有总账；`cleanupOldRecords` 尚未接入；这些是后续 P1（按人归集、月结对账）的工作，不在本决策内承诺。
- **操作约束**：不要把人民币金额直接填进 USD 字段；不要因为“有免费额度”把单价填 0（只有官方免费模型才填 0）；服务商控制台应开启“免费额度用完即停”，应用预算不能代替服务商扣费限制。
