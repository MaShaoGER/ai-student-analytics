# 后台管理构建路线与验收标准

确认日期：2026-10-19。

状态：阶段 0–5 已在本地实施并完成首期验收，阶段 6 数据导入留待后续。本文件保留为实施与验收依据；实际实现、口径及边界见[使用和迁移说明](admin-management.md)与[验收记录](admin-management-acceptance.md)。

## 1. 目标与顺序

先建立账号、操作权限、数据归属和全站运行概览，让后续上传的数据有明确的管理者和使用范围。

实施顺序：**权限基础 → 账号管理完善 → 数据集目录与授权 → 系统总览与操作日志 → 整体验收 → 数据导入**。

后台服务于现有教学分析业务。首期保持单站点、少量预设角色和数据集级授权，继续沿用已有应用与视觉风格。学校组织树、自定义角色设计器、多租户、审批流、收费系统不在首期范围。

“整站数据显示”分为两项：

1. 管理员查看真实运行数据，例如账号数量、数据集状态、分析请求和 AI 用量。
2. 管理员控制哪些数据集对哪些账号开放、哪些数据集可用于前台查询。

首页自由排版、任意菜单配置和推荐问题 CMS 留到后续；统计数值由实际数据计算，不能由管理员填写。

## 3. 首期产品范围

### 3.1 后台导航

建议设为“系统总览、账号管理、角色与权限、数据集管理、AI 配置、操作日志”。角色与权限可以先作为账号详情中的一个页签，无需为了菜单数量拆页面。“我的账号”继续保留。

继续使用现有双主题、工业风视觉、明确的加载/空状态/失败反馈和移动端布局。新增页面上的数据必须来自真实接口，禁止用随机数或示例卡片充当系统统计。

### 3.2 角色和操作权限

先采用三个预设角色，展示名与存储枚举可以分开：

| 操作 | 管理员 | 教师／分析人员 | 只读人员 |
| --- | --- | --- | --- |
| 查看允许范围内的数据画像、标准聚合图表 | 允许 | 允许 | 允许 |
| AI 对话分析 | 允许 | 允许 | 不允许 |
| 导出允许范围内的聚合结果 | 允许 | 允许 | 首期不允许 |
| 管理账号、角色、数据集授权 | 允许 | 不允许 | 不允许 |
| 管理 AI、预算和系统配置 | 允许 | 不允许 | 不允许 |
| 查看管理日志、全站用量 | 允许 | 不允许 | 不允许 |
| 上传导入 | 后续阶段实施 | 后续按权限开放 | 不允许 |

只读查看允许界面所必需的确定性统计查询，不允许借用该权限发起 AI 调用。前端有现算图表时，不能把所有 POST 查询一律当成写操作。

首期建议保留 `admin`、`user` 的既有存储含义，界面将 `user` 显示为“教师／分析人员”，新增只读角色。若必须改枚举，需显式迁移和兼容测试，不能让旧账号失去角色或误获管理员权限。

首期保留现有管理员保护：后台创建普通或只读账号，普通账号之间分配角色；不增加普通账号提升为管理员、停用或重置受保护管理员的入口。管理员本人改密沿用现有流程。

### 3.3 数据范围

- 操作权限与数据范围共同决定能否访问：有分析权限的账号也只能分析获授权的数据集。
- 首期按数据集授权；课程、学期、班级级授权随后扩展，不能在界面中宣称已支持。
- 内置数据集归属“系统”，未来上传数据集再引入明确的上传者、管理者和授权记录。
- 管理员可管理所有目录项；业务查询仍遵守数据集启停和实际可用状态。
- 数据集停用阻止新的业务查询和 AI 工具调用，管理页仍可查看和恢复；停用不删除源文件。
- “已停用”“未授权”“源文件不可用”分别处理。缺少 OULAD 文件不能被显示为可用数据，也不能报成无权限。
- 账号授权为空时显示真实空状态，不自动回退到全部数据集。

旧普通账号原本能使用两个内置数据源，迁移时显式保留既有范围；新增账号按管理员选择赋权。初始化和迁移必须幂等，不能每次启动又把已经撤销的权限补回。

### 3.4 账号操作

- 列表支持账号/显示名称搜索、角色和启停筛选，规模增长时使用有界分页。
- 创建、编辑、角色分配与授权都有校验、保存反馈和失败恢复；账号名首期保持不可修改，显示名称可编辑。
- 重置普通账号密码使用现有密码哈希方案；临时密码仅在必要的交付界面展示一次，要求下次登录修改，不写入日志或列表响应。
- 重置密码、停用和主动退出都撤销相应会话；角色或数据范围修改后，下一次请求使用最新权限。
- 暂不做硬删除账号，以停用保留审计关联；恢复启用不会恢复旧会话。

## 4. 后端必须统一执行的访问规则

权限规则放在公共服务层和请求边界，由各入口复用。菜单隐藏不能代替后端拒绝访问。

至少核对以下入口：

1. 数据画像、数据集列表、课程与学期目录。
2. 标准分析、分布、课程关系、全景及图表工坊的项目数据接口。
3. `/api/chat`、旧 `/api/ask`、推荐问题与本地降级路径。
4. AI 工具实际执行、历史上下文和结果引用处理。
5. 导出、报告及结果缓存；权限撤销后不能再从服务端获取旧范围数据。
6. 账号、角色、配置、授权、系统统计和日志接口。

先确认数据集访问权，再构造目录、调用模型或查询数据。客户端传来的角色、数据归属、历史消息与结果引用不能授予权限。已经下载到用户设备的文件无法撤回，不能宣称权限变更会删除本地副本。

现有 CSV/HTML 导出在浏览器完成，增加只读角色时必须处理这条路径：界面明确限制导出，新增服务端导出入口须鉴权；已允许查看的内容仍可被用户复制或截图，不能把“禁止导出按钮”描述成防复制或防泄漏能力。

缓存按数据集版本与授权边界设计。切换账号、撤销授权、停用数据集时刷新前台状态，不能把另一个账号的结果继续当作当前结果展示。

数据集目录首期可以登记并管理 `demo`、`oulad`，物理文件仍由已有受控映射解析。不要仅为后台目录把路径或任意 SQL 暴露给客户端；动态上传数据源的扩展在导入阶段实施。

## 5. 系统总览与日志口径

### 5.1 总览

| 指标 | 口径与限制 |
| --- | --- |
| 账号数 | 总账号、启用、停用、按角色分组；不等于在线人数 |
| 数据集状态 | 已登记、启用、当前可用分别计数；静态状态不冒充实时检测 |
| 分析请求 | 有明确记录的请求数；请求和多轮模型调用分开统计 |
| 完成情况 | 成功、部分完成、失败分开；仅在分母和分类可确认时计算成功率 |
| 请求耗时 | 按所选时间窗统计已记录请求的耗时，展示样本数；数据不足时不展示无依据的 P95 |
| AI 用量 | 模型调用、token、估算费用与估算标记，复用既有结算数据，不把估算当供应商账单 |

支持今日、近 7 天、近 30 天等有界时间窗，日界线按 `Asia/Shanghai`。记录保存 UTC 时间，界面说明显示时区。概览显示最近更新时间。

分析记录可能按阶段落盘，应先核对是否需要用 `requestId` 去重；旧记录缺字段时标明覆盖范围，不伪造关联。评测和连接测试若无法从记录可靠区分，必须写明是否混入统计，不能直接标为“真实用户业务调用”。

首期不承诺在线人数、持久会话数、历史报告总数、教学效果提升等当前没有可靠来源的指标。总览读取与列表需要有范围和上限，避免每次刷新都无界扫描全部日志。

### 5.2 操作日志

记录账号创建、资料修改、启停、角色/授权变化、密码重置、主动撤销会话、数据集启停和 AI 配置变更。

建议字段：事件 ID、时间、操作者账号 ID、动作、目标类型/ID、允许记录的变更摘要、结果、错误码和请求关联 ID。配置摘要只记录允许公开的状态变化。

不得保存密码、临时密码、令牌、API 密钥、完整请求体、对话正文或学生明细。管理操作日志与现有分析审计保持用途区分，不改写历史分析记录。

读取日志仅管理员可用，支持时间、操作者、动作和结果筛选及分页。明确保留期限和有界存储策略；需要清理时按已确认的期限执行，不在首次上线时顺带删除原有记录。实施时明确业务变更与审计写入的一致性，不能静默丢失高权限变更日志。

## 6. 分阶段实施与完成标准

### 阶段 0：检查工作区和设计最小改动

- 读 `AGENTS.md`、`/Users/mashao/.codex/RTK.md`、本文件与 `DEV_STATE.md` 顶部交接。
- 核对分支、工作树、现有未提交改动、运行中的开发服务和编译目录。
- 列出所有数据读取入口、存储结构、现有测试，形成简短的权限矩阵和迁移方案。
- 需要隔离分支时使用 `codex/` 前缀，并确保保留已有未提交基础；不从旧 `main` 开始导致本轮 AI 功能丢失。

完成标准：能说明本轮修改范围、旧账号如何兼容、权限在哪些入口落实，随后直接进入实施。

### 阶段 1：权限基础

实现预设角色、统一操作权限、数据集授权结构和幂等迁移，接入现有业务接口与 AI 工具边界。保持管理员原有保护。

完成标准：普通、只读、管理员的允许/拒绝路径可通过 HTTP 验证；伪造角色、切换接口、旧降级路径不能绕过；未授权请求不查询敏感数据、不调用模型。

### 阶段 2：账号管理完善

实现搜索筛选、资料编辑、普通/只读角色分配、数据集授权、密码重置、会话撤销，补齐前端状态和反馈。

完成标准：旧账号可继续登录；新增账号只能使用被授予的数据集；权限变化下次请求生效；重置密码后旧会话失效，新密码登录进入强制改密流程；受保护管理员不会被此入口锁出系统。

### 阶段 3：数据集目录与授权界面

登记内置数据源，展示来源、状态、可用性、能力和已知版本；支持启停与授权。保留未来导入的数据集 ID、归属与版本扩展点。

完成标准：停用后所有业务入口一致拒绝新查询，恢复后可用；未授权账号看不到目录详情、课程学期标签或画像；源文件缺失如实显示。当前声明版本不是文件内容哈希，不能声称已完成动态版本管理。

### 阶段 4：系统总览与管理日志

从现有持久记录计算有依据的总览，接入管理日志列表。AI 配置、预算、知识索引和本人账号设置继续可用。

完成标准：统计可用固定夹具独立复算；成功率、费用和调用口径明确；空数据、部分旧数据、记录损坏有诚实反馈；日志有权限、分页与敏感字段限制。

### 阶段 5：整体验收和交接

完成类型、单元/路由、隔离 HTTP、生产构建和真实浏览器验收；更新用户说明、接口/存储变更说明与 `DEV_STATE.md`。

完成标准：管理员、分析人员、只读人员的主要操作与拒绝路径在界面和服务端一致；刷新、重新登录、跨账号、权限撤销、深浅主题和窄屏状态通过。按实际结果记录完成、未完成和遗留项。

### 阶段 6：后续数据导入，本轮不实施

后台完成后再建设成绩 Excel/CSV 的上传、字段映射、质量检查、确认入库和 AI 分析接入。数据集归属、授权、版本、操作日志复用本轮基础。出勤/作业导入、班级权限、自定义角色另行安排。

## 7. 验证要求

权限和持久化变化必须覆盖以下回归：

- 匿名访问、普通账号访问管理接口、只读账号调用 AI、未授权数据集、批量/混合范围请求。
- 授权撤销、角色降级、账号停用、密码重置和会话撤销后的下一次请求。
- 所有相关接口、AI 工具、固定问题、降级与缓存路径中的同一限制。
- 旧状态迁移、重复迁移、并发更新和重启恢复；旧账号、配置、费用与审计不被覆盖。
- 越界分页、无数据、部分完成、历史字段缺失、日志敏感信息排除。
- 浏览器中的加载、错误、空权限、过期会话及账号切换。

按改动执行：

```bash
pnpm typecheck
pnpm test
pnpm test:api
pnpm test:recovery
NEXT_DIST_DIR=.next/admin-management-verify pnpm build
```

构建目录示例使用前检查是否被其他进程占用。开发服务和测试服务保持状态、端口与编译目录隔离，保留用户已有 `next-env.d.ts`、`tsconfig.json` 修改，不用全量还原覆盖。停止/清理只针对本轮创建并确认归属的资源。

编辑 Next.js 代码前按仓库要求读取 `node_modules/next/dist/docs/` 的相关指南。浏览器应实际操作新增后台，不能以通过类型检查代替运行时验收。权限测试优先使用隔离账号、模拟模型与临时状态，不调用真实供应商证明“未授权不会调用”。仅在涉及真实模型行为时开展必要的有费用验证，并如实记录范围。

已有 AI 真实评测的九项未通过和回答语义问题仍保留，见 [AI 回答可靠性记录](ai-answer-reliability.md)。本路线调整下一阶段优先顺序，不代表这些问题已解决，也不授权顺带修改评测期望掩盖失败。

## 8. 新对话入口

使用 [后台构建提示词](admin-build-prompt.md) 启动新对话。新对话默认完成阶段 0–5 的首期后台，不进入阶段 6；每阶段验证后继续下一阶段，直到首期验收完成或遇到确需用户决策的阻塞。

交付时说明完成能力、迁移影响、测试证据和剩余问题。提交、推送、合并与部署需遵守该对话的实际授权；本次文档编写没有执行这些动作。
