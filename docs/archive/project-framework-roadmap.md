原规划日期：2026-11-01；归档说明更新：2026-11-02。

状态：历史独立框架方案，不作为当前主项目的执行路线。本文原定“另建项目、旧项目仅供参考”，后续方向已调整为在原 Next.js + DuckDB 系统上改进数据浏览、保留账号权限、AI 与导入导出。当前能力与使用方式见[项目首页](../../README.md)、[工作台指南](../workspace-guide.md)，资料分类见[文档导航](../README.md)。

下文原有阶段、“待执行”和“尚未开发”等措辞保留为当时计划，不表示当前主项目尚未实现这些能力；也不作为独立原型现状的证明。

## 一、建设目标

先围绕两个主要功能，搭出一个能运行、能走通主要流程、方便继续细化的项目框架：

1. **数据探索**：首页看到图表和数字，点击看详情，再找相关数据、做对比，继续探索。
2. **AI 对话**：有独立入口，按主流聊天产品的习惯使用；需要时可以带着当前数据聊天。

先把结构和主要路线搭好，再逐项完善功能。框架不是几张只能展示的空页面，也不要求第一轮做完全部细节。

本路线图不按比赛评分分配功能，不确定视觉风格，不默认沿用旧项目的教育领域、页面结构和技术架构。比赛要求只作为原创、隐私及提交方面的约束。

旧项目仅供参考；本文不是旧项目已实现能力的说明，也不替换旧项目原有路线图。进入开发时使用独立分支和工作目录，避免直接改动旧实现。

## 二、整体结构

```text
网站公共框架
├── 数据探索
│   ├── 首页：图表、关键数字、浏览起点
│   ├── 详情：完整数据、筛选、来源和口径
│   ├── 关联：当前数据还能连接到什么
│   └── 对比：选择数据，查看差异，继续探索
├── AI 对话
│   ├── 新建与切换对话
│   ├── 消息输入、回复和生成状态
│   ├── 历史记录与恢复
│   └── 当前引用的数据
└── 共用基础
    ├── 路由与状态恢复
    ├── 数据查询与计算
    ├── 图表、指标和结果的统一格式
    ├── 会话与结果保存
    └── 加载、空内容、错误与重试
```

这里只有两个用户主功能。“共用基础”是内部支撑，不另做成一个庞大后台。

上面的划分是功能职责，不代表最终一定要做成对应数量的独立页面。详情用页面还是侧栏、聊天如何布局，留到后面决定。

## 三、框架搭建阶段

### 阶段 1：确定项目边界和基础约定

**做什么**

- 确定独立项目位置、启动方式，以及前端、服务端和共用类型的组织方式。
- 确定一小批可合法使用、能够实际查询的数据，供首轮接通流程；演示数据必须明确标注。
- 列出这批数据的指标、单位、时间、可筛选条件，以及能关联、能比较的内容。
- 确定首轮 AI 服务接入方式；正式密钥只放服务端，不写入仓库或浏览器。
- 明确首轮运行环境与访问方式；若开放给多人使用，保存的对话和访问权限必须隔离，不能共用私人历史。

**怎样算完成**

- 能说清楚项目怎么启动、数据从哪里来、AI 怎么接入。
- 有一条明确的示范探索路线，不再只有抽象功能名称。
- 数据和会话有稳定编号，后续页面能通过编号找到同一份内容。

**技术选择原则**

优先成熟、简单、能覆盖需求的组合。可参考 React + TypeScript、成熟图表库和一个模块化服务端；不因为旧项目用了某框架就必须继续使用，也不先拆微服务、引入图数据库或向量数据库。实际技术组合在开始开发时确定。

### 阶段 2：搭好网站公共框架

**做什么**

- 建立“数据探索”和“AI 对话”两个清楚、独立的入口。
- 搭建基础布局、内容区域和导航，先保证桌面及窄屏可使用，不做视觉定稿。
- 建立首页、详情、对比、对话的路由及状态规则。
- 统一最基本的加载中、无数据、失败、找不到内容等状态。
- 分开保存浏览状态与聊天状态，不能切换功能就把另一边清空。

**怎样算完成**

- 两个功能区可以来回切换，入口不是无效按钮。
- 浏览器前进、后退和刷新能够回到对应位置。
- 无效地址显示明确提示，不偷偷跳回首页，也不自动创建分析或会话。
- 页面结构清楚，没有把全部页面、请求和状态堆进一个工作台组件。

### 阶段 3：接通数据探索的主线

**做什么**

- 首页接入少量实际可查询的图表和关键数字。
- 点击图表或数字，能查看对应详情，并保留选中对象。
- 详情展示指标说明、数值、时间、单位、来源，以及首轮必要的筛选。
- 提供有明确理由的关联入口；首轮可以根据数据人工配置，不要求 AI 推荐。
- 提供最基本的对比流程，并说明不能直接比较的原因。
- 对比中的对象仍能继续进入详情，不把对比做成死胡同。

**怎样算完成**

走通以下真实路线：

> 首页 → 数据详情 → 相关数据 → 对比 → 继续查看 → 返回原位置。

- 选中一个点查看读数，与围绕这个点继续探索，是两个明确操作。
- 切换内容、返回和刷新后，必要的筛选及选中对象仍能恢复。
- 图表和表格使用同一份结果；数字不是写死的展示文案。
- 时间、单位或统计口径不兼容时，不强行叠图。

### 阶段 4：接通独立 AI 对话的主线

**做什么**

- 支持新建、发送消息、连续追问、切换历史对话。
- 接入真实模型，回复逐步显示；支持停止生成。
- 支持基本 Markdown、代码块和表格阅读。
- 保存会话，刷新或重新打开后可以恢复。
- 明确显示连接失败、生成失败和保存失败，提供适当的重试操作。
- 不带平台数据时，也能正常聊天，不限定为几个固定分析题型。

**怎样算完成**

走通以下真实路线：

> 新建对话 → 提问 → 逐步收到回复 → 连续追问 → 切换对话 → 刷新后恢复。

- 停止后状态正确，旧请求不会把内容写进另一个会话。
- 失败不会伪装成成功，也不会丢掉用户刚输入的问题。
- 固定回复或定时播放不能算真实模型接入；缺少密钥时明确说明不可用。

### 阶段 5：连接数据探索与 AI 对话

**做什么**

- 在数据详情和对比结果提供“带到对话中”的操作。
- 用户能看见本次引用的图表、指标和条件，并能移除。
- 聊天获得的是明确的数据引用和结果，不是偷偷带入整个浏览历史。
- AI 需要查询时，通过受控工具读取数据；统计数字由程序计算。
- 回答引用平台数据时提供可点击入口，能够返回对应详情或打开相关数据。
- 用户回到数据区时，原来的探索位置不丢失。

**怎样算完成**

走通以下真实路线：

> 查看数据 → 带入对话 → 提问并获得有依据的回答 → 打开回答中的数据 → 继续探索。

- 不强迫所有数据浏览经过 AI，也不强迫所有聊天引用数据。
- 数据不足时说明限制；猜测不能冒充来源明确的结论。
- 数据区和聊天区引用同一结果时，数值和筛选条件一致。

### 阶段 6：检查框架是否站得住

**做什么**

- 实际走完数据、聊天及两者衔接的三条路线。
- 检查刷新、前进后退、切换功能、切换会话、空数据、请求失败和停止生成。
- 检查桌面与窄屏，确保主要操作可见、可用。
- 整理实际启动说明、环境变量模板及当前已接通范围。

**怎样算完成**

- 两个主要功能独立可用，并且能够互通。
- 关键入口没有空跳转，未实现能力不以正常可用按钮冒充。
- 数据和 AI 使用情况标注真实；模拟数据、固定演示与真实能力有明确区别。
- 没有因为返回、刷新或切换功能而新增无关记录、丢失当前内容。
- 通过实际浏览器操作确认，不只以编译通过作为完成依据。

## 四、框架完成后，再逐项细化

以下能力进入后续细化，不要求在框架阶段全部完成，也不是默认取消：

| 方向 | 后续细化内容 |
| --- | --- |
| 首页 | 展示哪些数据、排序方式、发现入口、视觉层次 |
| 数据详情 | 更多筛选、图表操作、数值查看、指标解释 |
| 关联探索 | 更丰富的关系、推荐理由、探索路径展示 |
| 对比 | 多对象、多指标、时间对齐、不同口径处理 |
| AI 对话 | 编辑问题后重新回答、重新生成、历史管理、长对话阅读体验 |
| 两边衔接 | 多份数据引用、上下文更新提示、更多从回答进入数据的操作 |
| 视觉与体验 | 页面布局定稿、配色字体、响应式细节、必要的动效与性能优化 |

文件上传、语音、联网搜索、报告中心、账号管理后台等不默认进入本路线图；只有出现明确需求，再单独规划。

## 五、职责划分

| 模块 | 负责内容 | 边界 |
| --- | --- | --- |
| 公共框架 | 导航、路由、基础布局、状态恢复、公共状态提示 | 不包办所有业务 |
| 数据探索 | 首页、详情、关联、对比、浏览位置 | 不依赖聊天才能使用 |
| AI 对话 | 消息、生成、会话保存、引用数据的展示 | 不自行编造统计数据 |
| 共用数据服务 | 查询、计算、来源、口径、结果编号 | 不负责页面布局 |

模块划分不代表需要四个人；同一个人也按这些边界组织代码。

## 六、第一轮明确不做什么

- 不做视觉设计定稿。
- 不追求图表数量、模型数量或数据源数量。
- 不先建设庞大后台、复杂权限体系或运维平台。
- 不用预设长篇图表故事替代可分叉的数据探索。
- 不用固定问题匹配替代正常 AI 聊天。
- 不为比赛分数加入与两个主功能无关的能力。
- 不把旧项目的所有历史功能迁入新项目。

## 七、执行顺序与记录方式

执行顺序：基础约定 → 公共框架 → 数据主线 → 聊天主线 → 两边连接 → 框架验收 → 逐项细化。

每阶段完成后记录：实际接通了什么、验证了哪条操作路线、还缺哪些前提。不把规划项标成已实现；不以代码已创建或页面已出现代替验收。

当前所有阶段均为待执行。本轮只交付路线图；开始开发的第一个动作是确定独立开发位置、首轮数据和 AI 接入条件，而不是直接修改旧工作台。

框架完成的判断只有一句话：**数据能一路看下去，聊天能独立用，需要时两边接得上，后续细化不需要推倒重来。**
