# 会话历史加载状态修复

## 目的
切换数据源或会话时，如果旧的历史请求被 generation 作废，历史抽屉可能一直显示“正在读取历史”。统一处理失效时的加载状态，避免入口之间清理不一致。

## 方案
只在 `components/workspace.tsx` 内增加一个小的会话历史失效操作，并由相关入口复用。保留现有请求取消与 generation 守卫；失效旧请求时同时结束选择中和加载中的界面状态。

## 不做
不拆组件、不改 API、URL、会话存储、权限或数据口径；不触碰其他已知维护问题。

## 验证
验证“刷新历史后切换数据源”不再残留加载提示；检查新建对话与打开历史对话的加载/选择状态，并运行对应的定向测试、类型检查。
