# 指标语义边界修复（2026-11-15）

## 问题与修复

真实验收曾将“比较所有课程的出勤率和作业提交率”执行为 `completion_rate`。该指标实际读取课程完成标记，不能代表出勤、作业提交或作业完成。

本轮在 `c68d79d` 的既有未提交修复上继续修改，未提交、推送或部署：

- 为所有数据源提供基础工具支持的指标、定义与公式，而非只给导入数据设置能力清单。明确 `completion_rate` 的课程含义。
- 新增 `lib/ai/metric-request.ts`，区分明确的比率统计、定义问题、被否定的目标、显式课程完成率及已有出勤关系图/桑基图请求；作业完成率不会因包含“完成率”而被识别为课程完成率追问。
- 执行边界拦截仅请求不支持比率时的统计替代；即使模型仍选择 `completion_rate`，也在 SQL 执行之前终止。说明的是“当前 AI 聚合工具不支持按课程直接计算”，不谎称原始校园数据一定没有字段。
- 只请求不支持的比率时，给出明确限制和可选择的下一步，不返回替代图表或编造结果。若同时明确要求可支持的课程完成率，可返回这部分结果，并标记部分完成、说明未完成的比率。
- 定义与已有关系图继续走原流程，但关系图请求同样不能被换成课程完成率。
- 历史评测现在保存完整回答及聚合附件、结果引用、步骤和上下文。boundary-08 额外要求明确说明两项比率限制、且没有返回替代统计；不再仅凭返回类型认定成功。原有历史断言与失败报告保留。

这次没有增加新的比率计算功能，修复目标是准确说明能力边界并阻止错算其他指标。
