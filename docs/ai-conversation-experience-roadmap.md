# AI 对话体验规格与实施记录

日期：2026-10-20。状态：P1–P6 已在正式工作台实施并完成本地验收（2026-10-21）；真实模型语义、手机软键盘真机和远程发布不在已验证范围。使用与实现见 [正式体验说明](ai-conversation-experience.md)，存储与运维见 [历史存储说明](ai-conversation-storage.md)。

本规划承接 `/preview/ai-experience` 的用户体验确认，把现有 AI 分析、图表、表格和账号能力接入同一个对话流程。预览说明见 [ai-experience-preview.md](ai-experience-preview.md)，下一窗口开工指令见 [ai-conversation-experience-build-prompt.md](ai-conversation-experience-build-prompt.md)。

## 1. 已确认的产品要求

- 保留预览的整体布局、视觉风格和主题适配。左侧“预设对话场景”在正式页面改为账号历史对话；主区保留连续问答、分析过程、结论、数字依据和图表／表格附件；输入区保持可见。
- 历史随账号在服务端持久保存，账号间隔离。**自最后一条消息更新起保留 10 天**；继续发送消息或保存新的助手消息会续期，单纯打开、浏览、切换展示不会续期。
- 根据问题意图和数据语义选择合适的图表或表格，复用现有系统的计算结果和组件，不让模型自行编造数字、数据点或图表配置。
- 修复回答生成时直接跳到末尾的体验：提供可打断的平滑跟随，保留回答开头和当前阅读位置，回看历史时不抢滚动。
- 本轮已将确认后的布局接入正式工作台；预览继续用于无 AI 调用的固定片段回归。

以下未标“已确认”的具体文件、接口、阈值和分期均为实施建议，可按当前代码调整，但不得改变上述产品要求。

## 3. 按数据语义选择展示形式

### 3.1 决策顺序

1. 从服务端真实计算结果取得指标、单位、维度、时间顺序、样本、分母、聚合方式、数据缺失和隐私抑制信息。
2. 校验哪些展示形式成立，产生 `allowedViews`；字段不足或语义不成立的类型不进入候选。
3. 用户明确要求的形式在候选中时优先使用；不成立时给出简短原因，并采用可解释的替代形式。
4. 用户未指定时，结合问题意图、数据规模和可读性选择默认形式；图表旁始终可查看对应的精确数据表。
5. 纯图表／表格切换复用同一结果，不重新调用 AI、不重复统计，也不改变结果事实引用。

### 3.2 默认展示规则

| 问题／结果结构 | 默认形式 | 对应表格与限制 |
| --- | --- | --- |
| 单一指标、总量或变化值 | 数字摘要 + 必要范围说明 | 给出单位、样本和时间；不为一个值强行配图 |
| 无自然顺序的类别比较、排名 | 条形图 | 类别、指标、有效样本；长标签优先横向排列 |
| 有序时间的 3 个及以上观测点 | 折线图 | 时间、值、样本；缺失值断开，不补零，不把类别顺序伪装成趋势 |
| 同一指标两个时期的比较 | 哑铃图；不适合配对时用分组条形图 | 前值、后值、绝对变化、两期样本；不同人群只能解释为群体变化 |
| 及格率、参与率等比例的组间比较 | 条形图；有真实有序时间时可折线 | 同时展示分子、分母及百分比；变化写“百分点”，相对变化率另行标识 |
| 互斥且可加总的部分组成 | 少量类别可饼图，多类别优先条形图／矩形树图 | 必须有已知总体、非负数量和互斥关系；未知是否重叠时禁用组成图 |
| 分数分布、离散频数 | 直方／分箱柱图；二维分布可热力图 | 分箱边界、频数、样本和分箱口径；均分不足以生成分布 |
| 多组分布比较 | 有真实分位数时用箱线图 | 展示实际五数和样本，沿用项目当前须线定义，不凭均值推算分位数 |
| 实际阶段流转 | 桑基图 | 必须有真实来源、去向、流量；不从互不相关的汇总表编造流转 |
| 两个数值维度的关系 | 有真实成对记录时散点图；仅有联合分箱时热力图 | 明确样本与粒度；联合分布不冒充个人散点，关联不解释为因果 |
| 多课程共弱／共同选课、课程全景 | 现有关联／全景图 | 沿用共同样本、阈值及隐私规则，不改称相关系数 |
| 精确查值、多字段混合、类别很多 | 表格优先 | 搜索／排序按当前组件能力接入；大表分页或窗口化，避免一次展开所有行 |

建议超过 40 个类别时默认表格；若展示 Top N，应注明筛选和排序规则，并能查看完整结果。该阈值只影响展示，不改变统计总体或结论。雷达图仅在维度可比较、量纲和归一化依据明确时开放；不能把不同单位的原始指标直接放在同一雷达图上。

### 3.3 统一的数据与表格约束

- 均分、百分比、指数和重叠群体不相加构成“整体”。单位为“次”也不自动代表可加总。
- 数值列不等于连续度量：编号、学期编码和类别代码不得当作普通指标；日期必须按真实时间排序。
- 表格数值右对齐，列头或单元格明确单位；保留前后值、变化、分母和有效样本。排序和计算使用原始数值，格式化只在展示层进行。
- `null`、无记录、不适用和隐私抑制分别表达；不能显示成 0。沿用现有小样本保护规则，不在表格、导出或提示层绕过抑制。
- 图、表、结论及数字依据共用 `resultId` 和结果数据。展示切换保留结果身份；改变课程、学期、指标等查询条件才进入新的分析或现有合法重算流程。
- 不同时间窗口可并排说明，但须标明窗口差异，不能据此生成相关或因果结论。不能将缺勤缺失替换为学习活动，或把“请假加旷课”称为“旷课”。
- 导出继续遵循现有角色权限与数据集权限；不能因为新增历史或统一表格而扩大导出范围。

### 3.4 建议的代码边界

新增一个可独立测试的纯规则模块，例如 `lib/analysis/presentation-policy.ts`，输入为服务端可信的结果元信息和用户展示意图，输出默认形式、允许形式及选择／拒绝原因。语义元信息至少覆盖维度角色、时间顺序、单位、聚合方式、是否互斥可加总、缺失状态及可用的配对／分布结构；未知属性按不满足处理。

先为现有 `analysis`、`studio`、`distribution`、`relations`、`panorama` 编写适配器，避免重写计算工具。以可选字段渐进扩展 `ChatArtifact` 的展示信息；保留旧的 `view`、主 `artifact` 等兼容路径。专项结果的 `chart/table` 与通用结果的具体图表类型不同，不强行改成相同枚举。

`lib/ai/unified.ts` 负责产出真实结果；规则模块负责可用形式和默认选择；结果组件负责渲染。前端再次校验恢复出来的旧 `view`，非法形式回退到可用形式；没有可视化条件时回退表格或空状态，不静默画出有误导的图。

## 4. 正式页面和实际对话流程

沿现有 `ConversationWorkspace` 与结果渲染入口改造，不把预览的演示状态机复制为第二套业务流程。可抽出共用附件渲染器，让新布局继续使用现有计算和专项组件。主题与样式尽量局部收敛，避免覆盖工作区已有全局样式修改。

主流程为：输入问题 → 必要时澄清 → 已有执行状态 → 结论及数字依据 → 合适的图表／表格 → 带上下文追问。继续支持多附件、停止、超时、失败、部分完成、重试和引用定位；局部图表展开失败不能清空已完成的文字与证据。

侧栏显示新建对话和按最近消息时间排序的历史。标题从首个有效问题截取，不额外调用模型；显示最后消息时间和必要的数据集范围。支持显式删除；窄屏收进抽屉，切换历史后回到主区，输入区适配软键盘。

历史打开后恢复消息、最终状态、上下文和允许保存的聚合结果快照。旧执行步骤只能作为已完成记录展示，不能恢复成“仍在分析”。历史结果注明生成时间；数据集或指标版本变化时提示“历史结果”，继续追问重新查询。无法验证内容版本时不宣称历史结果仍是最新数据。

## 5. 账号历史与 10 天清理

### 5.1 时间语义

推荐字段：`createdAt`、`lastMessageAt`、`expiresAt`，统一采用服务端 UTC 时间。`expiresAt = lastMessageAt + 10 × 24 小时`，以 `now >= expiresAt` 判断过期。

- 首条用户消息成功保存时开始计时；后续实际消息新增或内容更新成功保存时更新 `lastMessageAt`。
- 助手处理中步骤、心跳、轮询和临时流式片段不是正式消息更新，不逐片续期；保存完整／部分／失败／停止的最终助手消息时更新一次。
- 单纯打开、搜索、切换图表、折叠附件、复制或导出不续期；这些展示状态不复写消息正文。
- 网络重放同一个已保存轮次返回原结果，不重复写入，也不续期。用户明确发起新的重试轮次可产生新的消息并续期。
- 过期对话不能因打开或发送到旧 ID 而复活；客户端提示已清理，并允许新建对话。

### 5.2 存储与 API 建议

初期优先复用 `lib/settings/storage.ts` 的持久目录、跨进程锁和原子写入，用独立的会话仓储封装；按账号分桶并限制消息大小、单会话长度与账号存储量。不要把所有账号的完整对话集中到一个不断增长的 JSON 文件。数据量增长后可替换数据库，接口层不依赖文件布局。

建议保存：会话 ID、服务端所有者 ID、标题、数据集范围、时间、修订号、存储结构版本，以及有界的消息、轮次状态、请求 ID、上下文和必要聚合结果。AI 上下文仍沿用现有历史长度限制，不能把十天全部历史送进模型。历史列表接口只返回摘要并分页，详情按会话获取。

建议接口职责如下，最终名称随当前路由约定调整：

| 接口 | 职责 |
| --- | --- |
| `GET /api/conversations` | 当前账号的未过期会话摘要，游标分页 |
| `POST /api/conversations` | 创建当前账号会话，校验数据集权限 |
| `GET /api/conversations/:id` | 当前账号会话详情，校验过期、当前数据集权限和结果可用性 |
| `DELETE /api/conversations/:id` | 删除自己的会话，重复删除保持幂等 |
| 现有 `POST /api/chat` 增量扩展 | 接受会话 ID、客户端轮次 ID 和期望修订号；服务端加载可信上下文并保存轮次 |

所有者来自现有服务端登录态，不接受客户端指定的 `ownerId`。读写均校验归属；管理员不能仅因角色就读取他人的对话。写接口沿用同源校验，响应采用私有不缓存策略；数据集授权撤销或停用后不能靠历史快照继续访问受限结果，侧栏也不泄露相关内容摘要。

对话正文存到专门的历史存储，不写进现有审计日志。仅保存业务必要的消息和经过允许字段筛选的聚合结果，不保存系统提示词、密钥、内部推理或学生级原始明细。预览固定对话不自动写入正式历史。

### 5.3 并发、失败和清理

- 同一会话同一时刻只允许一个活动分析；通过服务端原子领取轮次和修订号约束，客户端禁用按钮只是辅助。
- 客户端轮次 ID 绑定请求内容摘要。相同 ID 与相同输入可返回进行中状态或已完成结果；相同 ID 携带不同输入应拒绝，避免重复付费和重复消息。
- 耗时 AI／统计请求放在存储锁之外。分别原子保存开始和结束状态，结束时校验会话、轮次和修订，避免删除／过期后被迟到结果重新创建。
- 切换历史、退出账号时中止前端订阅，迟到响应不能写入另一个会话；服务端取消行为沿用现有请求控制。断线／重启后将无法恢复的运行标记为中断，不伪装成功，也不自动重复调用 AI。
- AI 已产出而历史保存失败时，区分“分析已完成”和“历史保存失败”；优先只重试持久化，不把按钮变成再次分析。
- 每次访问均严格过滤过期会话；另设服务端启动清理和定期清理任务，建议运行期间每 5 分钟清理一次。多进程下清理与续期、删除使用同一原子存储机制。
- 服务停止时没有后台进程执行物理删除；重启后先清理再提供历史。部署说明须写明这一区别，不能声称浏览器定时器实现自动清除。备份排除会话正文或采用同等保留策略；恢复时也先过滤过期项。

## 6. 滚动与动效

将滚动控制限制在对话容器内，避免整页和附件嵌套滚动相互抢位置。采用“跟随最新／用户回看”两种状态：靠近底部时允许跟随；向上滚轮、触摸、拖动滚动条或阅读导航立即打断；出现新内容时显示回到最新入口。

长回答整体到达时不要直接对齐回答末尾。先展示回答开头；仅在用户仍跟随且需要露出当前生成内容时推进。现有 SSE 主要为步骤状态时如实展示，不伪装成模型逐字流式生成。已有消息在下方新增内容、图表加载或高度变化后，应保持当前阅读锚点。

平滑跟随建议使用可取消的 `requestAnimationFrame` 控制器，在新目标出现时更新目标，不叠加多次原生 `smooth`；使用时间差推进而非固定帧数。尊重用户停止跟随，卸载时清理任务和监听器。图表初始化和容器展开后调用现有尺寸更新能力，不以频繁 React 渲染推动滚动。

附件折叠、引用定位、发送状态等只提供短促反馈。尊重系统减少动态效果和项目动效开关；键盘操作不被延时动画阻塞，焦点不随新消息移动，输入法组合态回车不发送。只通过合适的状态提示区域宣读执行变化，不把整个不断变化的结果设为实时播报区域。

## 7. 分期与完成条件

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| P1 展示规则与契约 | 纯规则模块、现有结果适配、兼容字段 | 语义决定允许形式；错误请求有明确回退；同一结果切换不再分析 |
| P2 布局与真实结果组件 | 确认后的正式布局、复用图表／表格和引用 | 固定真实结构 fixture 能走通比较、趋势、澄清、多附件和失败状态 |
| P3 历史服务 | 仓储、列表／详情／删除、TTL、轮次幂等 | 账号隔离、重启保留、10 天边界及并发清理测试通过 |
| P4 串联现有流程 | `/api/chat` 增量接入、上下文恢复、取消与存储失败恢复 | 完整流程可用；跨会话响应不串线；重复轮次不重复执行 |
| P5 滚动和动效 | 平滑可打断跟随、历史回看、附件尺寸处理 | 长回复与延迟图表不抢阅读位置，减少动态效果和移动端可用 |
| P6 验收与文档 | 自动检查、浏览器验收、部署清理说明 | 明确已通过项与未验证项，保留预览离线体验和来源说明 |

P1 与 P3 可由不同子代理在明确文件边界后并行；P2 依赖展示契约，P4 依赖历史接口，最后统一验收。采用小批次可回退提交，不让子代理同时修改对话主组件或共享类型。

## 8. 必须覆盖的验收

### 结果与表现形式

- 两学期均分示例仍为 72.72 → 69.65，下降 3.07 分，两期有效样本分别为 199／200；图表、表格、结论和依据一致，不将其解释为同一批学生的个人退步。
- 类别排名、三期以上趋势、比例及分母、真实分布、双时间窗口、重叠类别、缺失值、全零和空结果分别选择正确形式；无分位数不开箱线图，无真实配对不造散点图。
