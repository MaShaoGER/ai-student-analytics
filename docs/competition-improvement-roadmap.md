## 第二批：AI 深度与可见的执行过程

### 1. 标准 Function Calling 与受控多步分析

- 先验证当前实际使用的模型、协议和端点是否支持标准工具调用，再逐步接入。参考[阿里云官方 Function Calling 文档](https://help.aliyun.com/en/model-studio/qwen-function-calling)。
- 将现有聚合查询、成绩分布和高级图表封装为有明确参数 Schema、权限检查和结果类型的工具；复用 `runAnalysis`、`scoreDistribution`、`executeChartTool` 等现有能力。
- 增加明确的“综合分析”入口，按任务需要进行多步规划与执行。普通单步问答继续使用合适的轻量路径。
- 设定工具调用次数、总耗时和总费用上限；多步调用共同遵守单次请求预算，保留取消、失败降级和审计。具体上限在兼容性验证后确定。
- 兼容性不满足时保留现有路径并如实标识；现有 JSON 决策与程序派发不作为标准 Function Calling 的完成证据。

示例任务：

> 找出本学期均分下降最多的课程，再看它的成绩分布，并总结值得进一步核查的现象。

验收：先明确比较学期与可比口径，再查询课程变化，根据真实返回结果选择后续分布工具；结论数字一致，缺少可比数据时澄清或说明限制，不编造下降原因。覆盖超限、取消、工具失败和重复调用场景。

### 2. 带引用的教学知识检索（RAG）

- 第一版知识范围：指标定义与公式、数据字典、数据来源及统计限制，以及来源明确、带版本的课程说明和教学规则。
- 指标知识尽量从现有指标定义生成，减少代码与文档漂移；人工维护内容记录来源、版本和适用范围。
- 建立小规模检索索引，命中后将相关片段提供给模型；回答展示引用与版本。根据实际检索质量和规模再决定是否引入独立向量数据库。
- 无依据、来源冲突或超出适用范围时明确说明；检索材料作为数据处理，不授予执行权限。统计数字仍来自查询工具。

示例问题：“完成率和出勤率有什么区别？”

验收：准备可回答、无依据、来源冲突的问题集，分别检查检索命中、引用准确性和拒绝编造能力，并与现有直接回答作对照。

### 3. 界面展示真实执行阶段

- 在消息中展示实际发生的阶段，例如“检索指标说明 → 执行学期比较 → 查询成绩分布 → 校验结果”。
- 支持展开简短执行记录、耗时、数据范围与引用，展示可核对的操作摘要。
- 阶段状态由真实执行事件驱动；协议设计需与当前一次性 JSON 契约、取消、审计和预算一致，并同步评估及更新 [ADR 0003](adr/0003-no-streaming-yet.md)。逐字流式输出暂不列为最低完成范围。

验收：正常、空结果、失败、停止和重试的状态均与服务端实际执行一致，晚到事件不污染新请求；桌面和窄屏可读。

## 可选后续：多模态与数据接入

上述功能稳定后，再评估“课程汇总表截图识别 → 人工校对 → 绘图”。首版限定不含学生个人标识的汇总表，展示识别依据与不确定项；字段、数值和样本口径须经校验后才能进入分析。

通用 CSV/Excel 全站导入需要字段映射、格式校验、缺失值提示、导入预览、数据版本和权限设计，作为独立功能批次排期。现有图表工坊的本地文件读取不视为全站导入已完成。

## 优先顺序与完成边界

1. 基础修正与评测。
2. 当前模型的标准工具调用兼容性验证、受控多步分析、RAG 和真实执行过程。
3. 统一报告、对话保存与效果验证；赛事材料同步准备。
4. 核心功能稳定后，再决定是否开展多模态和通用数据导入。

推荐优先交付范围：**基础修正 + 标准工具调用 + 带引用的 RAG + 真实执行过程 + 统一报告**。对话保存和效果验证仍列入第三批，多模态与通用导入按剩余时间单独决定。

单人持续投入前三批粗估 12–18 个工作日，材料可同步准备；这是排期参考，需在模型兼容性和报告契约验证后调整。

实施时按改动风险运行相关测试；AI 工具、RAG 和持久化需覆盖关键回归，协议与图表变化需做浏览器验收，发布前再完成构建、HTTP、真实模型和候选部署检查。所有完成状态以实际证据更新。
